# Transcript Cleaner 非语义重复清理 PRD

## 1. Executive Summary

**Problem Statement**

中文转写稿中存在由 ASR、翻译、剪辑或说话重启产生的无语义增量重复。现有规则可能漏掉短片段的 `A + gap + A` 重复，也可能把排比、对比、强调等有语义作用的重复误判为错误。

**Proposed Solution**

为 Transcript Cleaner 建立按重复单位、距离和关系分层的规则算法。程序自动删除高置信的转写型重复和口语重启型重复，保留可能具有语义功能的重复，并将不确定项写入审计报告。

**Success Criteria**

- 清理结果中不存在符合自动删除条件的 `A + gap + A`，其中 `A` 至少 3 个中文字符，`gap` 少于 15 个字符。
- `A` 与 `gap` 的字符计数包含中文标点符号。
- 完全相同的相邻整句和相邻句块重复清理率达到 100%。
- 排比、对比、递进、强调和教学复述测试集的误删数量为 0。
- 每次自动修改均记录类型、位置、修改前后文本和置信度。

## 2. User Experience & Functionality

**User Personas**

- 需要把中文 ASR 或 Whisper 转写稿整理为可读文稿的内容编辑者。
- 需要批量清理课程、播客、访谈文字稿的自动化系统维护者。

**User Stories**

**Story 1**

As a 内容编辑者, I want to 自动删除无语义增量的口吃和重启 so that 文字稿可以连续阅读。

Acceptance Criteria:

- 删除连续单字或短词口吃，例如 `我我我觉得`。
- 删除明确短语重启，例如 `我觉得……我觉得这件事很重要`。
- 删除高置信的句内短间隔重启。
- 删除后保留完整、可读的实际表达。

**Story 2**

As a 系统维护者, I want to 删除 ASR 或翻译循环产生的整句和句块重复 so that 输出不再包含机械复制内容。

Acceptance Criteria:

- `A。A。` 只保留一份。
- `A。B。C。A。B。C。` 只保留一组。
- 支持两个及以上句子的可变长度句块。
- 支持段落内部和引号内部的连续句块重复。

**Story 3**

As a 内容编辑者, I want to 保留具有语义作用的重复 so that 清理不会损坏作者原意。

Acceptance Criteria:

- 保留排比、对比、递进和强调。
- 保留教学中的有意复述。
- 保留专有名词和主题词的自然复现。
- 包含新实体、数字、因果、否定或对比信息时不得自动删除。
- 近似重复或改写重复只写入报告。

**Story 4**

As a 系统维护者, I want to 查看每次清理的审计记录 so that 可以定位误删并调整规则。

Acceptance Criteria:

- JSON 报告包含规则类型、位置、置信度及修改前后文本。
- 自动删除项和仅报告项可以区分。
- 报告包含各规则命中次数和字符变化。

**Non-Goals**

- 不删除所有结构相似或语义相近的句子。
- 不自动删除近似改写、观点重述或教学复述。
- 不使用 LLM 判断重复意图。
- 不负责翻译、摘要、事实校正或全文润色。
- 不定义 Markdown 转 EPUB 的实现。

## 3. AI System Requirements

**Tool Requirements**

- 第一版使用确定性的 Python 文本处理规则，不调用 LLM。
- 输入为 UTF-8 中文 Markdown。
- 算法必须保留 Markdown 标题、列表、代码块和段落结构。
- 输出必须包含清理后的 Markdown 和 JSON 审计报告。

**Evaluation Strategy**

建立带人工标签的测试集，至少覆盖：

- 词级口吃。
- 短语重启。
- 句内短间隔重启。
- 相邻整句重复。
- 相邻与嵌入式句块重复。
- 近似改写。
- 排比、对比、递进、强调和教学复述。

核心断言：

```text
A >= 3 个字符
0 <= len(gap) < 15 个字符
pattern = A + gap + A
```

字符长度按 Unicode 字符计数，中文标点计入长度。测试程序必须扫描清理结果，确认不存在仍符合自动删除条件的目标模式。

评估指标：

- 高置信重复清理召回率：100%。
- 语义重复误删数：0。
- 已标注自动删除样本测试通过率：100%。
- 已标注保留样本测试通过率：100%。

## 4. Technical Specifications

**Architecture Overview**

```text
Markdown 输入
  -> 结构保护
  -> 候选重复检测
  -> 风险分类
  -> 高置信规则修改
  -> 不确定候选记录
  -> 残留模式扫描
  -> Markdown + JSON 报告
```

检测维度：

- 重复单位：字、词、短语、分句、整句、句块。
- 重复距离：紧邻、短间隔、跨句、跨段。
- 重复关系：完全相同、去口头词后相同、前缀重复、包含关系、近似改写。
- 重复意图：通过保守规则推断；无法高置信判断时不修改。

处理风险：

- 低风险：自动删除连续口吃、完全相邻整句和完全相邻句块。
- 中风险：自动删除并报告明确重启和短间隔重复。
- 高风险：近似重复、改写、排比、对比和强调只报告。

句内短间隔重启规则：

```text
A + gap + A
A + gap + A + continuation
```

自动删除必须同时满足：

- `A` 至少包含 3 个中文字符；标点计入字符长度。
- `gap` 少于 15 个字符；标点计入字符长度。
- `gap` 主要由停顿标点、空白或允许的口头连接词组成。
- 第二个 `A` 与第一个完全相同，或第二段完整包含第一个 `A`。
- `gap` 不包含新的实体、数字、因果、否定或对比信息。
- 删除前一个 `A` 后，后一个表达仍完整。

**Integration Points**

- 集成到现有 `transcript_cleaner.cleaner` 清理管线。
- 沿用现有 CLI 的 Markdown 输入和 JSON 报告格式。
- 新规则必须提供独立统计字段和编辑类型。

**Security & Privacy**

- 全部处理在本地完成，不上传文字稿。
- 不覆盖原始输入文件。
- 输出路径必须由调用者明确指定。
- 规则异常时保留原文，不执行猜测性删除。

## 5. Risks & Roadmap

**Phased Rollout**

- MVP：实现 `A >= 3`、`gap < 15` 的完全匹配检测、删除和残留扫描。
- v1.1：支持允许口头词集合及 `A + gap + A + continuation`。
- v2.0：建立更完整的近似重复候选报告，但仍不自动删除。

**Technical Risks**

- `A` 仅 3 个字符时容易匹配自然语言中的正常复现，必须限制 `gap` 内容并检查语义保护信号。
- 标点计入长度后，连续引号、括号或 Markdown 标记可能影响边界识别。
- 简单正则可能跨越 Markdown 标题、列表或代码块，必须先保护结构。
- “删除后更通顺”无法由纯规则完全判断，因此边界样本必须保留并报告。
- 残留扫描不能把明确要求保留的语义重复算作失败；扫描结果必须结合自动删除条件判断。
