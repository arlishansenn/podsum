#31 只实现真实 atomic file/outbox connector：Send/retry 只能由 local owner 对当前 confirmed Brief 的实际 facet fingerprint 触发。delivery store 与 VIA history 都是锁定、fsync、append-only 的 durable store；history 只投影 Action Gateway receipt 引用及安全 action/outcome，绝不公开 token、memo、cost 或 payload。SMTP 是后续人工 cutover/manual smoke 授权范围，当前不会自动 SMTP。

daemon 只绑定 `127.0.0.1:8787`，提供 `/health`、`POST /trigger/email-evidence-gateway`、`POST /trigger/workbench-action`、`GET /via/email-evidence-pack`、`GET /via/email-intel-brief`、`GET /via/email-review`、`GET /via/history`、`GET /receipts` 和 `GET /status`。WorkbenchAction Gateway 有 `evidence_action`、`brief_action`、`review_action`、`delivery_action` 四个独立 facet；delivery 只 feed Brief，绝不 wake Evidence。Brief 同时维护完整 backing `state/email-intel-brief-via.json`（含 `delivery`）和 kernel 确定性生成的 reviewable backing `state/email-intel-brief-reviewable.json`（完整对象删除 `delivery`）。完整和 reviewable named facet 分别读取这两个文件，runtime 严格验证投影一致；缺失或不一致 fail closed。Review 只订阅后者，Review Agent 从该实际 backing 读取，deterministic merge 仍读取完整 Brief backing：candidate、revision、confirm 内容或 status 变化会自然唤醒 Review，纯 delivery 变化的 reviewable fingerprint 稳定，因而不会产生 Review receipt。Brief 的 candidate/revision 使用公开 `createAgentRender`；Agent 在 `state/email-intel-brief-via.json` 写严格 `{title,summary,claims,gaps}` transient proposal，每个 claim 只含 `{text,evidence_entry_ids}`。除 `state/email-intel-brief-via.json` 外的所有 harvested `world_model` files（包括未知或 authority-looking path）都是不可信 scratch：runtime 完全丢弃，绝不读取、验证或 commit，且不能影响 truth；runtime 从 final 经 kernel `briefWorld(final)` 重算仅有的两个 backing。runtime 先严格拒绝 proposal 内 extra/authority 字段、未知或 redacted/tombstone EvidenceEntry ID，再由 kernel 从当前 Evidence VIA 构造固定 identity/source/status、canonical claim ID、完整 coverage、revision decision 与 not_requested delivery，调用 final validator 并生成两个真实 backing 后才发布。Agent 永不提供或覆盖 claim_id、source、coverage、status、decision、delivery、brief_id、version。Review candidate 的 Agent 只写严格 `{verdict,findings}` transient proposal；runtime validator 从当前 reviewable backing 计算 binding/fingerprint，kernel 确定性构造 stable agent Review ID 和完整 collection 后才发布。confirm、human review merge、resolve 和 delivery projection 是 deterministic，confirm 永不发送。Brief GET 额外返回只读 receipt `via_fingerprint` 以绑定 action，且不属于 Brief truth。

Brief proposal prompt 的一次 omission root cause 已修复：原 contract/suffix 没有把「存在 current、未 redacted、非 tombstone evidence 时 `claims` 不得为空」明确给 Agent，因而模型可能提交 `claims:[]`，再由 deterministic validator 拒绝。现在 contract、suffix 和 proposal validator 一致要求非空；仅 0 available entries 允许空数组，并要求原样复制 upstream entry IDs、为 material assertion 引用证据。

#32 adds a semantic source guard to the production Brief routing: a named Brief facet at cold→null has no prior and must call the Agent; a `request_revision`, or a current Evidence ledger revision/material fingerprint different from `prior.source`, also calls the Agent. Confirm and delivery stay deterministic. When the source is unchanged and there is no Brief-relevant action—including an explicit null action baseline or a `submit_review` that only changes `review_action`—the runtime performs a zero-cost deterministic no-op that copies the complete prior Brief and both validated backings. This prevents a first review submission from superseding the current Brief fingerprint.

#27 的两个 contract copy live test 是 isolated evidence-module test，不单独证明 production full host；完整 production composition 由 wrapper 的 checked-in `src` 默认集和 #30/#31 full-set tests 继续覆盖。#27 的 durable source of truth 是 `EmailEvidenceLedger` 文件，不是模型输出，也不是 Workbench review sidecar。`outputs/email/evidence_ingress.py ARTIFACT LEDGER REACTOR_ENDPOINT` 是唯一 ingress seam：它用 Python kernel 严格验证规范化 artifact、锁定并原子替换完整 append-only ledger snapshot、生成 commit envelope，最后 POST 到 `email-evidence-gateway`。HTTP 失败时 ledger 已提交，调用方可以安全重送同一 artifact。Gateway 和 Email Evidence Responsibility 只维护该 kernel commit 的 Reactor projection；`evidence_pack_via` 是唯一可见 facet。

责任的 `name` 与固定项目生成的 `id` 相同，避免 Forme 将 human-readable name 当作 node identity，造成 `no contract fingerprint` 的持续 compile failure。

#31 delivery identity is `sha256(canonical(confirmed Brief without delivery) + configured target)`. The action stores both its mutable current VIA target fingerprint and `brief_content_fingerprint`; this permits an exact original-action replay after the delivery projection changes, and permits retry with a new current VIA fingerprint while retaining the delivery ID and attempt sequence. UI-level lost-response replay resubmits the same `action_id` through Workbench: Workbench reads the original exact history binding instead of rebinding the changed current Brief, returns `idempotent: true` with the current Brief, and never POSTs the daemon. `tests/email-intel-brief-validator.test.cjs` mechanically verifies the two Brief facets and their delivery/status fingerprint boundary; `tests/email-delivery-live-blackbox.test.cjs` keeps the live Workbench replay assertions for unchanged file bytes/mtime, history count, and receipt count.
