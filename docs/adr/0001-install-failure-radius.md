# 安装动作按失败半径分给脚本或人

`scripts/install.sh` 自己创建 Python 运行环境、安装 Node 依赖、重载定时任务，
却拒绝安装 ffmpeg、拒绝调用 Hermes skills 安装脚本，只打印命令让人自己执行。
这个不一致是有意的：判据是**失败半径**——只影响本进程、且可本地回滚的动作由脚本
做；会改动系统状态、或影响其他正在运行的应用的动作由人做。

## 分类结果

| 动作 | 谁做 | 失败半径 |
|---|---|---|
| 创建 Python 运行环境、装依赖 | 脚本 | 全在部署目录内，删掉重来 |
| 安装 Node 依赖 | 脚本 | 同上，且 lock file 已入库，可精确复现 |
| 重载定时任务 | 脚本 | 纯本地，失败立即非零退出 |
| 安装 ffmpeg 等系统工具 | 人 | 改动系统级 package manager 状态 |
| 安装／刷新 Hermes skills | 人 | 会重启另一个正在运行的应用 |
| 升级 pip | 人 | 改动运行环境之外的工具链 |

## 被否决的替代判据

「是否需要联网」。它推不出上表：脚本自己做的运行环境创建同样联网，而且下载量
远大于一次系统工具安装。联网与否区分不了这两类动作，失败半径可以。

## 后果

新机器上的安装不是一条命令走完，而是「跑脚本 → 照提示装几个外部工具 → 再跑一次
脚本」。这是刻意的：外部依赖的安装会失败，而失败时人应该在场。看到 preflight 只
提示不代装时，不要把它当成未完成的自动化去「补全」。
